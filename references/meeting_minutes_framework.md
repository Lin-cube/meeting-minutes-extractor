# 会议纪要框架（references）

本文件是 meeting-minutes-extractor 技能的参考资料，供指令路径使用：当你需要**不跑脚本、直接用自然语言**整理会议纪要时，按本框架执行。

## 什么是「好的会议纪要」

一份合格的会议纪要，不是「把每个人都说了什么抄下来」，而是让**没参会的人**看完后能回答四个问题：

1. 这次会议**要达成什么**（目标）
2. 最终**定了什么**（决策）
3. **谁**在**什么时候**之前**做什么**（行动项）
4. 还有什么**没定**、**有风险**、**要跟进**（未决 + 风险 + 下次）

## 纪要四要素（核心）

| # | 要素 | 要回答的问题 |
|---|------|------------|
| 1 | 目标 | 这次会议为什么开？成功标准是什么？ |
| 2 | 决策 | 讨论后**已经拍板**了什么？ |
| 3 | 行动项 | 谁、做什么、什么时候做完、现在什么状态？ |
| 4 | 跟进 | 什么还没定？什么有风险？下次什么时候对？ |

## 决策 vs 行动项（最容易混的两件事）

- **决策（decisions）**：结论性的判断，例如「v2 聚焦打卡提醒和共读小组 MVP」。
- **行动项（action_items）**：由决策派生的具体任务，例如「李雷在 2 月 25 日前开发打卡提醒接口」。

一个决策往往派生多条行动项；没有行动项的决策，大概率会「会后没人做」。

## 行动项四要素（SMART 化）

每条行动项都要满足：

- **行动**：做什么（动词开头，越具体越好）
- **负责人**：谁来做（写名字，不写「大家」「有人」）
- **截止时间**：什么时候完成（具体日期）
- **状态**：待开始 / 进行中 / 已完成 / 已阻塞

格式：`{行动} | {负责人} | {截止时间} | {状态}`

## 未决问题与风险

- **未决问题（open_questions）**：会上讨论了但**没结论**的事，需要单独列出继续跟进。例如「小组人数上限暂未确定」。
- **风险与阻塞（risks）**：可能影响进度的事。例如「系统通知可能被部分机型拦截」。

这两类信息最容易被「漏记」，因为它们不是「结论」，但恰恰是后续执行最容易踩坑的地方。

## 会议纪要完整度自检（6 维度）

一份纪要是否合格，可对照这 6 个维度打分：

| 维度 | 检查点 |
|------|--------|
| 基本信息 | 是否写清标题、日期、参会人 |
| 目标明确 | 是否写清了会议目标 |
| 纪要记录 | 是否记录了会议核心内容 |
| 决策清晰 | 是否提炼出关键决策 |
| 行动落地 | 行动项是否含负责人/截止时间 |
| 后续明确 | 是否有下次会议安排或未决问题 |

6 项全中 = 完整可用；缺 1–2 项 = 基本可用但有缺口；缺 3 项以上 = 纪要信息不足。

## 常见坑

1. **把会议记成流水账**：只记「谁说了什么」，不提炼决策和行动，会后没人知道该干嘛。
2. **决策和行动混在一起**：写「我们要做打卡提醒」，但没说谁做、什么时候做完。
3. **行动项写「大家」「尽快」**：没有负责人和截止时间，等于没有行动项。
4. **漏记未决问题**：没结论的事不记，下次开会又从头讨论一遍。
5. **纪要不迭代**：行动项执行完不回填状态，纪要就变成「死文档」。

## 指令路径的整理步骤

1. 先确认基本信息（标题 / 日期 / 参会人 / 时长）。
2. 把讨论内容按议题分段，每段收敛成「结论」。
3. 提炼决策清单 + 行动项清单（行动项补全负责人 / 截止 / 状态）。
4. 单独列未决问题与风险。
5. 确认下次会议安排。
6. 输出纪要 + 完整度自检，并诚实标注缺失项。
